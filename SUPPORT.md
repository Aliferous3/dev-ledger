# Support

Use the channel that matches the problem.

## Bug reports

Open a GitHub issue using the **Bug report** template when you can safely describe the problem publicly.

Include the affected page, selected range, browser, reproduction steps, expected behavior, and actual behavior. Remove repository names, private screenshots, tokens, and other sensitive information.

## Feature requests

Use the **Feature request** template. Describe the problem first, then the proposed behavior.

## Account or private-data problems

Use Dev Ledger's in-app feedback drawer when the report contains account-specific context or a screenshot that should not be posted publicly.

## Security vulnerabilities

Do **not** use a normal issue. Follow [SECURITY.md](SECURITY.md).

## Service status

For a production problem, first retry on [devledger.site](https://devledger.site) and confirm whether the issue is reproducible after a refresh. If the problem persists, report it with the minimum data necessary to investigate.
